# Лабораторная работа №3

**Выполнил:** Мацкевич Кирилл

## Цель работы
Расширение программной системы «Служба доставки» иерархией классов: выделение базовой сущности «Транспорт» и трёх специализированных сущностей («Мотоцикл», «Машина», «Грузовик») с общими характеристиками и специфическими свойствами, использование наследования для исключения дублирования кода.

* `Vehicle.h` / `Vehicle.cpp` — базовый класс «Транспорт» с общими характеристиками (ID, грузоподъёмность, курьер, статус, текущий заказ), защищённым конструктором и единой проверкой грузоподъёмности `validate_capacity()`.

1. **Иерархия классов:** публичное наследование `Motorcycle`, `Car` и `Truck` от `Vehicle`; общие данные и методы описаны только в базовом классе, производные добавляют лишь специфические свойства.

4. **Повторное использование кода:** операторы сравнения и ввода-вывода реализованы один раз в базовом классе и работают для всех типов транспорта; оператор `>>` производных классов использует оператор базового класса и запрашивает только специфические поля.
5. **Ограничения предметной области:** грузоподъёмность не может превышать максимум для типа транспорта, объём багажника ограничен диапазоном 100–2000 л, запрещено изменять ID, грузоподъёмность и статус транспорта во время выполнения заказа.

# Лабораторная работа №4

**Тема:** Полиморфизм, виртуальные функции, абстрактные классы  
**Выполнил:** Мацкевич Кирилл  
**Группа:** 550501

## Цель работы
Расширение иерархии классов транспорта механизмами динамического полиморфизма: превращение базового класса в абстрактный, реализация виртуальных методов в производных классах и единообразная работа с разнотипными объектами через указатель на базовый класс.

---

## Структура проекта
* `Vehicle.h` / `Vehicle.cpp` — абстрактный базовый класс с чисто виртуальными методами (`get_type()`, `get_max_capacity()`, `perform_specific_action()`, `get_specific_action_name()`, `calculate_delivery_cost()`), виртуальным `get_full_info()`, виртуальным деструктором и методом `can_carry()` для проверки возможности перевозки груза.
* `Motorcycle.h` / `Motorcycle.cpp`, `Car.h` / `Car.cpp`, `Truck.h` / `Truck.cpp` — производные классы, переопределяющие все виртуальные методы (`override`) со своими тарифами и специфическими действиями.
* `DeliveryService.h` / `DeliveryService.cpp` — класс-менеджер с коллекцией `std::vector<std::unique_ptr<Vehicle>>` и полиморфными операциями над всем транспортом.
* `ConsoleUI.h` / `ConsoleUI.cpp` — консольное меню: специфические действия и расчёт стоимости доставки для всего транспорта и для выбранного объекта.
* `Order.h` / `Order.cpp`, `InputUtils.h` / `InputUtils.cpp`, `main.cpp` — сущность «Заказ», безопасный ввод данных, точка входа.

---

## Основной функционал
1. **Абстрактный базовый класс:** `Vehicle` содержит чисто виртуальные методы, поэтому объект базового класса создать нельзя; объекты создаются только для производных типов.
2. **Специфическое полиморфное действие:** `perform_specific_action()` (переключение термокороба, проверка вместительности багажника, переключение гидроборта) и `calculate_delivery_cost()` (расчёт стоимости доставки по тарифу конкретного типа транспорта) — результат зависит от фактического типа объекта.
3. **Коллекция указателей на базовый класс:** объекты `Motorcycle`, `Car` и `Truck` хранятся в одной коллекции `std::unique_ptr<Vehicle>` и обрабатываются единообразно.
4. **Полиморфные вызовы:** вывод информации о всём транспорте (`<<` вызывает виртуальный `get_full_info()`), выполнение специфических действий для всего транспорта, расчёт стоимости доставки груза заданного веса для каждого транспорта, название специфического действия в меню через `get_specific_action_name()`.
5. **Управление временем жизни объектов:** владение объектами через `std::unique_ptr` (автоматическое удаление, в том числе при отклонении дубликата ID, без утечек памяти) и виртуальный деструктор в базовом классе.
6. **Проверка возможности перевозки:** метод `can_carry()` используется при назначении заказа, подборе подходящего транспорта и расчёте стоимости доставки.

# Лабораторная работа №5

**Тема:** Шаблонные классы и функции  
**Выполнил:** Мацкевич Кирилл  
**Группа:** 550501  

---

## Цель работы
Разработка универсального механизма хранения и обработки объектов, не зависящего от конкретного типа данных, и демонстрация его применимости к нескольким пользовательским классам, разработанным в предыдущих лабораторных работах.

---

## Структура проекта
* `Collection.h` — шаблонный класс-контейнер `Collection<T>` (добавление, удаление по индексу, доступ по индексу, поиск по значению, подсчёт элементов, очистка, вывод содержимого) и шаблонная свободная функция `find_if_matching()` для поиска элемента по произвольному предикату.
* `CollectionDemo.h` / `CollectionDemo.cpp` — демонстрационное меню, показывающее работу `Collection<T>` на двух независимых экземплярах: `Collection<Order>` и `Collection<Car>`, с ручным вводом всех полей объектов через `operator>>`.
* `Vehicle.h` / `Vehicle.cpp`, `Motorcycle.h` / `Motorcycle.cpp`, `Car.h` / `Car.cpp`, `Truck.h` / `Truck.cpp` — иерархия классов транспорта; `Car` используется как один из двух типов-параметров шаблона.
* `Order.h` / `Order.cpp` — класс «Заказ», используется как второй тип-параметр шаблона.
* `DeliveryService.h` / `DeliveryService.cpp` — класс-менеджер бизнес-логики, хранящий транспорт и заказы.
* `ConsoleUI.h` / `ConsoleUI.cpp` — главное консольное меню, переход в демонстрационное меню шаблонного контейнера.
* `InputUtils.h` / `InputUtils.cpp`, `main.cpp` — безопасный ввод данных, точка входа.

---

## Основной функционал
1. **Шаблонный контейнер:** `Collection<T>` реализует полный набор операций (добавление, удаление по индексу, получение по индексу, поиск по значению, подсчёт элементов, очистка, вывод) единым кодом для любого типа `T`.
2. **Шаблонная функция поиска по критерию:** `find_if_matching<T, Predicate>()` принимает лямбда-выражение и возвращает указатель на первый подходящий элемент коллекции — не зависит ни от типа `T`, ни от конкретного условия поиска.
3. **Применение к разным типам:** один и тот же шаблон использован для `Order` (самостоятельный класс) и `Car` (класс из полиморфной иерархии `Vehicle`), без создания отдельных реализаций контейнера под каждый тип.
4. **Прямой ввод данных пользователем:** добавление заказа и машины в демонстрационную коллекцию выполняется через перегруженные операторы `operator>>` соответствующих классов — пользователь вводит все поля объекта самостоятельно, а не через заранее заданные демонстрационные значения.
5. **Демонстрация независимости от предметной области:** одинаковый интерфейс `Collection<T>` работает как с объектами без иерархии наследования, так и с объектами, участвующими в динамическом полиморфизме, что подтверждает универсальность реализации.

# Лабораторная работа №6

**Тема:** Исключения и обработка ошибок  
**Выполнил:** Мацкевич Кирилл  
**Группа:** 550501  

---

## Цель работы
Расширение программной системы «Служба доставки» механизмом обработки исключительных ситуаций: определение ошибок, возможных при выполнении основных операций, создание собственных классов исключений и корректная обработка ошибок без аварийного завершения программы.

---

## Структура проекта
* `Exceptions.h` — иерархия собственных классов исключений. Общий базовый класс `DeliveryException` наследуется от `std::runtime_error`; от него унаследованы `InvalidDataException` (некорректные данные), `NotFoundException` (обращение к несуществующему объекту), `DuplicateIdException` (повторяющийся уникальный номер), `ConstraintViolationException` (нарушение ограничения предметной области) и `InvalidOperationException` (недопустимая операция над объектом). `NotFoundException` и `DuplicateIdException` дополнительно хранят номер объекта.
* `Order.h` / `Order.cpp` — проверка веса заказа в конструкторе, `set_weight()` и `operator>>`; запрет изменения номера и веса заказа, который уже доставляется.
* `Vehicle.h` / `Vehicle.cpp` — проверка грузоподъёмности (`validate_capacity()`), веса груза (`validate_cargo_weight()`), недопустимых операций при назначении заказа и завершении доставки.
* `Motorcycle.cpp`, `Car.cpp`, `Truck.cpp` — проверка специфических характеристик (объём багажника, флаги термокороба и гидроборта) при создании и вводе.
* `DeliveryService.h` / `DeliveryService.cpp` — проверка уникальности номеров, существования объектов и допустимости операций (удаление и назначение заказов, смена номеров).
* `Collection.h` — выход за пределы коллекции (`std::out_of_range`) при обращении и удалении по индексу.
* `ConsoleUI.h` / `ConsoleUI.cpp` — единая точка обработки ошибок `report_exception()`: каждый тип исключения обрабатывается своим `catch` с отдельным сообщением.
* `CollectionDemo.h` / `CollectionDemo.cpp` — собственная обработка ошибок демонстрационного меню шаблонного контейнера.
* `InputUtils.h` / `InputUtils.cpp`, `main.cpp` — безопасный ввод данных, точка входа.

---

## Основной функционал
1. **Собственная иерархия исключений:** пять специализированных классов с общим предком `DeliveryException`, что позволяет обрабатывать как конкретную ошибку, так и любую ошибку службы доставки одним `catch`. Сообщения формируются в момент `throw` и содержат конкретные значения (номер объекта, фактический вес, допустимый диапазон).
2. **Обнаружение ошибки там, где она возникает:** некорректные данные проверяются в конструкторах и сеттерах (`Order`, `Vehicle` и производные), дубликаты и отсутствующие объекты — в методах `DeliveryService`, превышение грузоподъёмности — в `Vehicle`, выход за границы — в `Collection`.
3. **Различная обработка разных ошибок:** `report_exception()` содержит отдельные обработчики для каждого типа (ошибка поиска, ошибка уникальности, некорректные данные, нарушение ограничения, недопустимая операция), затем для `DeliveryException`, `std::out_of_range`, `std::exception` и `catch (...)`. Порядок обработчиков идёт от частных к общим.
4. **Продолжение работы после ошибки:** все операции меню выполняются внутри `try`, после обработки исключения программа возвращается в главное меню. Ввод чисел защищён от нечисловых символов, поэтому некорректный ввод не приводит к завершению программы.
5. **Корректное состояние объектов после ошибки:** все проверки выполняются до изменения данных, поэтому при исключении объект не остаётся наполовину изменённым. Конструкторы бросают исключение до создания объекта, некорректные `Order`, `Car` и другие объекты не существуют.
6. **Безопасное управление ресурсами:** транспорт хранится в `std::unique_ptr`, поэтому при исключении (в том числе при отклонении дубликата номера) память освобождается автоматически, без утечек.
7. **Исключения только для исключительных ситуаций:** обычные случаи (неверный пункт меню, внутренний поиск объекта) обрабатываются без исключений: `find_*_index()` возвращает `-1`, для предварительной проверки есть `check_vehicle_exists()` и `check_order_exists()`.

Разбор значений через `std::from_chars`, многоуровневая проверка данных при загрузке.
* `Logger.h` / `Logger.cpp` — журнал событий: каждая запись добавляется в конец файла (`std::ios::app`) в формате `время | событие | подробности`. Сбой записи в журнал не прерывает работу программы, а выводит одно предупреждение в `std::cerr`.
* `ReportWriter.h` / `ReportWriter.cpp` — формирование текстового отчёта: сводка (транспорт по типам, свободный и занятый, суммарная грузоподъёмность, заказы по статусам и районам, суммарный вес), затем полные списки транспорта и заказов.
* `TimeUtils.h` / `TimeUtils.cpp` — получение текущей даты и времени для журнала и отчёта (локальная зона, при её недоступности — UTC).
* `Exceptions.h` — добавлены `FileOpenException` (файл не открыт), `FileIOException` (сбой чтения или записи) и `FileFormatException` (ошибка формата данных, хранит номер строки файла).
* `Vehicle.h` / `Vehicle.cpp`, `Motorcycle.cpp`, `Car.cpp`, `Truck.cpp` — виртуальные методы `get_type_code()` и `get_specific_field()` для сериализации без проверки типа объекта; метод `restore_assignment()` для восстановления связи с заказом при загрузке.
* `DeliveryService.h` / `DeliveryService.cpp` — методы `restore_assignment()`, `get_vehicles_count()`, `get_vehicle_by_index()`, `get_orders_count()`, `get_order_by_index()` для чтения и восстановления состояния.
* `ConsoleUI.h` / `ConsoleUI.cpp` — пункты меню сохранения, загрузки и формирования отчёта, автозагрузка при запуске, автосохранение при выходе, журналирование операций и ошибок.
* `Order.h` / `Order.cpp`, `Collection.h`, `InputUtils.h` / `InputUtils.cpp`, `main.cpp` — остальные части системы без изменений структуры.

## Формат файла состояния
```
DELIVERY_STATE;1
VEHICLES;2
CAR;1;1200;Иванов Иван;0;2;250
MOTORCYCLE;2;40;Петров Пётр;1;-1;1
ORDERS;2
1;ул. Мира, 25;12.5;Северный;0
2;ул. Ленина, 10;5.5;Центральный;1
```
Запись транспорта: `тип;номер;грузоподъёмность;курьер;свободен;номер текущего заказа;специфическое поле`. Запись заказа: `номер;адрес;вес;район;назначен`. Связь транспорта с заказом хранится номером заказа (`-1`, если транспорт свободен), а не указателем.

## Основной функционал
1. **Сохранение состояния:** вся система (транспорт всех типов, заказы и их взаимосвязи) записывается в файл через `std::ofstream`. Тип объекта и его специфическое поле определяются виртуальными методами, поэтому код сохранения не зависит от конкретных классов.
2. **Загрузка состояния:** файл читается через `std::ifstream`, объекты создаются обычными конструкторами с проверкой ограничений предметной области. После загрузки состояние программы совпадает с состоянием на момент сохранения, включая назначенные заказы.
3. **Восстановление связей в два этапа:** сначала загружаются все транспортные средства и заказы, затем связи восстанавливаются по номерам через `restore_assignment()`, поэтому порядок записей в файле не важен.
4. **Автозагрузка и автосохранение:** при запуске состояние загружается из файла (если файла нет, создаются тестовые данные), при выходе сохраняется автоматически. Если сохранённый файл не удалось загрузить, автосохранение отключается, чтобы пустое состояние не затёрло повреждённый файл.
5. **Безопасная загрузка:** новое состояние строится во временном объекте и подменяет текущее только после успешной загрузки; при ошибке текущие данные остаются нетронутыми.
6. **Журналирование:** в журнал записываются запуск и завершение программы, добавление и удаление объектов, назначение и завершение доставки, изменения характеристик, сохранение, загрузка, формирование отчёта и все возникшие ошибки.
7. **Текстовый отчёт:** сводная статистика и полные списки транспорта и заказов с датой формирования.
8. **Проверки при работе с файлами:** успешность открытия (`FileOpenException`), ошибки чтения и записи (`FileIOException`), корректность формата — заголовок, версия, секции, число полей, числовые значения, флаги 0/1, неизвестный тип, лишние данные в конце (`FileFormatException` с номером строки). Дополнительно проверяются ограничения предметной области, уникальность номеров, существование связанных объектов и согласованность статусов транспорта и заказов. При сохранении запрещены символ `;` и перевод строки в текстовых полях, чтобы не нарушить формат файла.
